# Banking redesign review — 1 November 2026

**The core redesign is in place, but the app-wide redesign is incomplete.** Overview, Plan, Personal, Spending budget, Settings, Add expense and the Monthly review stages have new page layouts. Categories and Expenses have partial adaptation. The other 31 screen routes still need a dedicated page-level pass; many inherited new colours/buttons without changing their structure.

The existing code already acknowledges this in BR5, despite marking the overall task done. BR5 and BR9 are now marked partial in [PLAN.md](../../PLAN.md). [flow.md](../../flow.md) describes the actual navigation and task journeys, including current return-path inconsistencies.

## What is working visually

The main pages retain the approved white/navy hierarchy, restrained rounded boxes, clear financial amounts and coloured solid icon tiles. Spending budget uses the intended wheel and three-value summary, with accessible category rows and an explanation of net movement. Personal's dark appearance remains coherent and preserves visible privacy wording. These are useful foundations to reuse for secondary pages.

Keep the concept and the existing banking components. Remaining work is to carry them through the full journeys, not start another visual direction.

## Findings, in priority order

### R-01 · High · Primary destinations open legacy page layouts

Bills, Goals, Income, Forecast and Balance check are prominent Plan entries but still use the earlier title/body/button-stack layouts. For example, [Goals](../../src/features/goals/goals-screen.tsx) displays three large creation/tool buttons before the first goal and a separate Open button per item; the current synthetic preview visibly confirms this. [Income](../../src/features/cashflow/income-screens.tsx) still wraps sources and occurrences in individual cards. [Bills](../../src/features/payments/payments-screen.tsx) retains two sets of choices, multiple descriptive lines per schedule and a separate View button.

**Next change:** redesign each entire route family, including lists, detail, edit, confirmations and error/empty states. Use the existing `DetailHeader`, `ListRow`, `ListSection`, `IconTile` and field controls where appropriate. Keep forms readable and preserve all decision/consent information rather than hiding financial essentials to shorten a page.

### R-02 · High · Back navigation still reflects the previous app structure

[Root Stack](../../src/app/_layout.tsx) hides system headers. Many inherited detail/list screens have no top Back affordance and place navigation at the bottom. Bills, Goals, Forecast and Reconciliation use `router.replace('/')` for their bottom Home action. [Income](../../src/features/cashflow/income-screens.tsx) uses `router.replace('/cash-flow')`, even after entry from Plan or Personal. [Bill editor](../../src/features/payments/payment-editor.tsx), [record-payment](../../src/features/payments/payment-paid.tsx) and [history](../../src/features/payments/payment-history.tsx) replace to `/payments` without preserving a private-space filter.

These are reachable routes, not dead links, but the destination can surprise the user and discard the entry context. The copy sometimes still says Home or Private where the new navigation says Overview or Personal.

**Next change:** define contextual Back/Cancel/success rules for each family; use history with a safe parent fallback where appropriate and preserve visibility parameters. Direct-link loads also need an exit. Keep unsaved/uncertain financial-action guards intact; do not blindly replace every route call.

### R-03 · High · Monthly review guide does not track the new stages

**Source-confirmed integration mismatch; full live-provider reproduction still required.** [Guide registry](../../src/features/guides/registry.ts) advances from `money-date-review` to `money-date-close` on the same `/money-date` route. [MoneyDate](../../src/features/money-date/money-date-screen.tsx) only mounts the close target when local `stage === 2`. [Guides provider](../../src/features/guides/provider.tsx) advances stored guide progress/routes but does not set that local stage; it deactivates an active guide after 1.5 seconds when the target is absent.

Expected failure path: start the review guide on stage one → tap its Next → progress points to the absent stage-three target → no close instruction, then guide deactivation. Resuming the close step on a freshly mounted review can have the same mismatch. Keeping IDs/version 1 avoids a schema migration but does not solve this visibility problem.

The old Money Date preview (since deleted) manually changes fixture state and `initialStage` when its mocked guide advances. That behaviour is not supplied by the real provider, so the preview cannot establish this integration works.

**Next change:** make guide progression stage-aware or supply an explicit preparation step that takes the user to the correct stage without submitting an approval. Preserve saved progress/dismissal. Add an integration check with the real guide provider, not only the mocked preview: start, Next, Back, resume close, refresh and dismiss.

### R-04 · Medium · Plan's booster subtitle describes a different feature

The current [translation](../../src/i18n/locales/en.json), `banking.plan.boostersHint`, says **“Add to a category for one week.”** [Boosters](../../src/features/relationships/boosters-screen.tsx) instead earmarks a completed week's unused category budget toward a shared goal, using explicit repeating weekly limits. The Plan preview displays the misleading subtitle.

**Proposed copy:** “Put weekly leftovers toward a goal.” Keep detailed weekly-limit explanations inside Boosters. This is a copy defect, not evidence that the financial calculation is wrong.

### R-05 · Medium · The global expense action needs task-specific review

[QuickLogLauncher](../../src/features/quick-log/launcher.tsx) hides itself only on Add expense and Pending expenses. It therefore also appears on signed-in bill/income/goal forms, Settings, receipts and Monthly review. On non-main screens it uses a floating action, which adds a competing task and can interfere with bottom content at large text/keyboard sizes.

**Evidence limit:** code confirms presence; overlap is a device/layout verification item, not a demonstrated screenshot defect from the synthetic harness. Decide which task screens should suppress it or reserve space. Keep quick entry readily available on main tabs without covering Save, Confirm or Cancel.

### R-06 · Medium · Secondary visual coverage is not current

The banking preview renders six page bodies, not all 40 routes. The earlier Phase 1.8 preview imported the removed `src/app/(tabs)/settings` path; it has since been deleted, and its old screenshots in `.impeccable/review/` are historical evidence only. The current typecheck does not validate every hidden preview harness.

**Next change:** restore a current fixture preview for each route family, including states and native/web chrome. Keep fixtures isolated from real mutations. Require current route-level acceptance before marking BR5/BR8/BR9/BR10 complete.

## Completion order

- [ ] **Pass 1 — Bills:** list, detail, editor, payment recording and history. Preserve actual amounts, payment-cycle linking, visibility and uncertainty handling.
- [ ] **Pass 2 — Income and forecast:** sources/occurrences, contribution editor, forecast, balance setup and corrections; maintain actual/expected distinctions.
- [ ] **Pass 3 — Goals and relationship tools:** goals, sinking editor, detail/history, gifts, boosters and expense splits. Keep explicit reviews and consent.
- [ ] **Pass 4 — Balance and review:** reconciliation and Monthly review guide integration. Preserve closing eligibility, approvals, hashes and locks.
- [ ] **Pass 5 — Spending details:** expense list/classification/conversation, categories/editor/assignment and receipt viewer.
- [ ] **Pass 6 — First use:** auth, create/join, invitation review and four-step budget setup. Retain resumable progress and optional guides.
- [ ] **Pass 7 — Supporting screens:** reminders, Guides, queue/offline and developer setup; refresh loading/error/direct-link states throughout.
- [ ] **Pass 8 — Acceptance:** current previews for all route families; installed iOS/Android, responsive web, dark/light, text scaling, keyboard/screen reader, account switching, offline restart and live two-partner flow.

For each pass, accept the list → detail → edit → save/cancel → return journey together. Completion requires the approved hierarchy, icon language and radius system, not just a different palette. Route URLs and financial contracts remain stable unless a separately reviewed fix requires otherwise.

## Non-issues and limits

- Moving Spending budget and Settings outside tabs intentionally removes the tab bar on those detail routes; provide Back rather than reintroducing extra tabs.
- Deeper icon colours differ from the pastel raster concept for contrast; this alone is not an unfinished redesign.
- Keeping labels for recorded versus expected money, private visibility and consent is necessary clarity, even when it uses more space than the mockup.
- The extreme negative forecast in the synthetic Plan preview comes from mixed fixture data, not an established live calculation defect.
- Existing financial bugs in BUGS.md remain tracked separately; this review did not fix them or re-audit production.

Changes in this task are documentation only: flow map, page inventory, corrected completion statuses and review findings. No remaining runtime page has been marked redesigned by this review.
